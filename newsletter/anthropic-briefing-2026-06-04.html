01 A model, a mega-round, and a path to the public markets

Lead Story · The throughline of the window

If you read only one thing about this period, read it as three moves in one direction. On 28 May, Anthropic made Claude Opus 4.8 generally available and announced a $65 billion Series H that put post-money valuation at $965 billion, with self-reported run-rate revenue that "crossed $47B earlier this month." The round was led by Altimeter, Dragoneer, Greenoaks, and Sequoia, co-led by Capital Group, Coatue, D1, GIC, ICONIQ, and XN, and folded in $15B of previously-committed hyperscaler money (including $5B from Amazon) plus memory/chip partners Micron, Samsung, and SK hynix. Several outlets framed it as Anthropic overtaking OpenAI as the most valuable AI company.

Then, on 1 June, the corporate-structure shoe dropped: Anthropic confidentially submitted a draft Form S-1 to the SEC. It is a Rule 135 announcement — no share count, no price — so it legally separates "we can IPO" from "we will." But it is the move that typically precedes a 6–12-month IPO window, and it converts the long-running funding rumors (a "$30B at $900B" leak we tracked on 27 May; the WSJ/TechCrunch "first profitable quarter" narrative) into something concrete you can cite in a vendor-risk conversation.

The funding rumors are now first-party numbers. $47B run-rate and a $965B valuation are figures you can put in a budget memo — not press speculation. Series H announcement · 28 May 2026

The skeptics arrived on schedule. Michael Burry ("The Big Short") publicly argued neither SpaceX nor Anthropic is worth $1T (134 pts on Hacker News), and The Economist's "Can the stockmarket swallow Anthropic, SpaceX and OpenAI?" was the single most-discussed thread of the window at 712 points / 1,257 comments. None of that changes the operational picture — but if you are quoting the Series H valuation to justify spend, expect the counter-narrative in the same meeting.

Why it matters The through-line for builders: the company you depend on is simultaneously shipping its most capable model at flat pricing, raising at a near-trillion-dollar valuation, and laying IPO groundwork. Read that as stability of roadmap — and as growing pressure to convert subsidized usage into per-token revenue, the pricing shift Simon Willison flagged this week (see §9).

02 Models & the API

What changed for people calling the Messages API

Claude Opus 4.8 — a same-price capability bump

Model string claude-opus-4-8, GA 28 May, available everywhere (API, Claude Code, claude.ai, Cowork) on day one. The platform facts that matter for building:

  • Pricing unchanged from 4.7: $5 / Mtok input, $25 / Mtok output; fast mode $10 / $50. Fast mode on 4.8 is roughly 3× cheaper than on prior models (2× the standard rate for 2.5× the speed).
  • 1M-token context by default; 128K max output. Effort defaults to high on every surface, including the raw API, with adaptive thinking (reasoning only fires when a turn needs it). /effort xhigh exists for the hardest tasks.
  • Prompt-cache minimum lowered to 1,024 tokens — cheaper to cache short system prefixes than on 4.7.
  • Reliability claim: ~4× less likely than Opus 4.7 to let flaws in its own code pass unremarked; the Alignment team reports misaligned-behavior rates "similar to" Mythos Preview. Launch-tester benchmarks: 84% on Online-Mind2Web (computer use), first model past 10% overall on a Legal Agent Benchmark, Genie multimodal at 61% lower token cost than 4.7.

Two Opus-4.8-only Messages API features — no beta header

  • Mid-conversation system messages. You can now place role:"system" entries at non-first positions in the messages array to update instructions mid-task while preserving prompt-cache hits — instead of routing changes through a user turn. Directly useful for long-running agents that need to revise permissions, token budgets, or environment context mid-run.
  • Refusal categories in stop_details. When Opus 4.8 declines, the API returns a refusal category so you can route different refusal classes to the right next step instead of string-matching error text. By 3 June (Claude Code v2.1.162 / agent-SDK v0.3.162) the same stop_reason:"refusal" and stop_details also land on local-session and SDK transcripts.
Multi-cloud note As of Claude Code v2.1.158 (30 May), Auto mode is available on Bedrock, Vertex, and Foundry for Opus 4.7 and 4.8 — opt-in via CLAUDE_CODE_ENABLE_AUTO_MODE=1. Previously the auto-approval classifier was first-party only. If you route through a hyperscaler for compliance or billing, you no longer give up the layer that (per Anthropic) catches ~83% of overeager behaviors.

No new model since. Opus 4.8 remained the newest first-party model through 4 June; Mythos stays gated to Project Glasswing (see §5). The base anthropic-sdk-* packages did not move in the final stretch — the Opus-4.8 feature adds landed in anthropic-sdk-python v0.105.0 and anthropic-sdk-typescript sdk-v0.100.0 on launch day.

04 The SDK lockstep

Agent SDKs realign after a 10-day Python stall

For most of the window the Python agent SDK lagged a full Claude Code cycle behind TypeScript. That gap is now closed.

  • claude-agent-sdk-typescript moved in lockstep with Claude Code (v0.3.152 → v0.3.162). Notable: v0.3.160 fixed hook callbacks swallowing abort signals; v0.3.161 made initialize idempotent and live-applies agent changes; v0.3.162 changed the default search behavior on native builds — SDK sessions now default to embedded find/grep in Bash rather than registering the dedicated Grep/Glob tools.
  • claude-agent-sdk-python resumed shipping after stalling at v0.2.87 since 23 May: v0.2.88 (2 Jun) ported session stores from raw asyncio to anyio, fixing a Trio crash; v0.2.89 (3 Jun) is a CLI-parity bump. TS and Python are back in the same cohort (v0.3.162 / v0.2.89 / CLI 2.1.162).
Action item If you run an SDK orchestrator with hook-based search auditing (canUseTool / interception on Grep/Glob), verify it still fires after upgrading — the dedicated tools are no longer registered by default on native builds. Name them explicitly in tools / allowedTools to keep the old behavior.

05 Security & cyber — Glasswing, Mythos, and a year of threat data

The most consequential research thread of the window

Project Glasswing tripled — and pivoted to patching

The 2 June "Expanding Project Glasswing" post (178 pts / 247 comments) is the substantive update. Partners went from ~50 to ~150 organizations across 15+ countries, now spanning power, water, healthcare, communications, and hardware — well beyond the original software cohort. Partners have surfaced more than 10,000 high-or-critical-severity flaws, and the program made its first explicit pivot from finding vulnerabilities to disclosing, fixing, and deploying patches — with Mythos Preview now writing patches and running pre-release checks. Claude Security is named as the productized form (Opus 4.8 scanning codebases and suggesting patches).

Read the fine print on "Mythos in the coming weeks" The Glasswing post explicitly conditions a Mythos-class general release on "highly robust safeguards… that we (and, to our knowledge, all other AI developers) have yet to develop." Treat the 28 May launch line about Mythos arriving "in the coming weeks" as conditional, not committed. A new "Cyber Verification Program" would grant Mythos-class access to additional orgs for specific cyberdefense tasks — no public details yet.

A year of AI-enabled cyber threats, mapped to MITRE ATT&CK

The 3 June Frontier Red Team post analyzed 832 accounts banned for malicious cyber activity (Mar 2025 – Mar 2026; partial results also published in Verizon's 2026 DBIR). The findings reset some common heuristics:

  • Threat level is inflating. The share of actors rated medium-risk-or-higher rose from 33% in the first half to 56% in the second (~1.7×).
  • AI is moving deeper into the kill chain. AI-assisted phishing (initial access) fell 8.6%; AI for post-compromise account discovery rose 8.9%. Malware-writing is still the most common use (67.3%); lateral movement is rare (6.5%) but a bigger risk signal.
  • Old signals broke. Technique count and which surface was used (Claude Code vs API vs chat) no longer correlate with risk. The durable signal is scaffolding architecture — whether the actor chains attack stages with autonomous decision-making. Anthropic is in talks with MITRE about extending ATT&CK with agentic-orchestration techniques.
If you build abuse / DLP / agent-audit tooling The "number of techniques" heuristic is now publicly deprecated by the vendor. Feature-engineer toward whether model-generated activity chains stages autonomously, not how many distinct techniques it touches.

The Mythos evidence trail

Across the window the Mythos story moved from rumor to hard data point. A claude-mythos-1-preview model string and a "Claude Security" dashboard were reported (unconfirmed) inside Claude Code on 25 May. More concretely, Apple credited "Calif.io in collaboration with Claude and Anthropic Research" for kernel integer-overflow bug CVE-2026-28952 (macOS Tahoe 26.5) — and a high-voted HN thread (145 pts) surfaced an Anthropic engineer's on-record line that the team "built a working exploit in five days" with Mythos Preview. It is the strongest external confirmation yet of the Glasswing/Mythos workflow producing a shipped, CVE'd OS-vendor vulnerability.

06 Research & engineering

Two reads worth your time

"How we contain Claude across products" — the highest-leverage single read

Published 25 May, it front-paged on HN (139 pts) on 4 June and is now the canonical citation for the v2.1.160–162 design choices. The numbers practitioners keep quoting:

  • Users approve roughly 93% of permission prompts. Claude Code auto mode cuts prompts by 84% and catches ~83% of overeager behaviors before they execute…
  • …but auto mode blocks only ~0.4% of benign commands while ~17% of overeager actions still get through — so it is defense-in-depth, not a substitute for a sandbox.
  • Three containment tiers documented (gVisor for claude.ai; Seatbelt/bubblewrap HITL sandbox for Claude Code, with the runtime open-sourced; full local VM for Cowork), plus three on-record near-miss incidents and Gray Swan numbers (Opus 4.7 holds attack success to ~0.1% single-shot, ~5–6% after 100 adaptive attempts).

"Coding agents in the social sciences" — adoption, quantified

A 27 May Economic Research post surveyed 1,260 quantitative social scientists. The headline gap: 81% have tried AI chatbots, but only 20% regularly use coding agents — and among those, Claude Code dominates at 86% (Codex 31%). Adoption is steeply uneven (economists 39%, public health 6%; >2× the rate for typically-male vs -female names; top-25 universities ~40% higher). Usage is overwhelmingly code, not prose. Rare first-party, quantified evidence for an internal adoption/ROI case — and a preview of the disparity findings that will surface in governance conversations.

10 The practitioner's checklist

Ten days of changes, distilled to what you should actually do
  1. Rename your triggers. Update docs, scripts, and hooks that key off the word workflow → ultracode (v2.1.160).
  2. Floor your Claude Code version at 2.1.156+ if you run Opus 4.8 (thinking-block API-error fix); 2.1.162 is current.
  3. Re-test hook-based search auditing. Native SDK builds now default to embedded find/grep; name Grep/Glob in tools/allowedTools if you intercept them.
  4. Add retry-with-fallback for model incidents — --fallback-model won't save you from 5xx on a model that exists.
  5. Rotate anything exposed. Treat pre-v2.1.161 claude mcp output / screencaps as leaked secrets.
  6. Enable Auto mode on Bedrock/Vertex/Foundry (CLAUDE_CODE_ENABLE_AUTO_MODE=1) if you route through a hyperscaler.
  7. Check stray MCP timeout values. A timeout:500 was silently aborting every tool call before v2.1.162; sub-1000 ms now falls back to the default.
  8. Reach for mid-conversation system messages for long-running agents that need to revise instructions without busting the prompt cache (Opus 4.8 only).
  9. Expect a cache-metrics discontinuity at v2.1.152 — cache_creation_input_tokens was previously under-reported in some configs.
  10. Re-tool your abuse/agent-audit features toward autonomous stage-chaining, not technique counts (3 Jun MITRE post).
